# 路书 · 设计方案

> 一个独立的小工具：把小红书上截到的行程，变成地图 App 里**带途经点、可直接出发**的多段路线。
> 本文是它的完整方案——产品定义、动线、架构、关键决策及其依据。
> 接口层面每条结论的证据与来源见 [`RESEARCH.md`](RESEARCH.md)。

---

## 1. 定义

**一句话**：截图内容贴进来，一键把所有目的地/途经点送进地图。

**场景**：你在小红书刷到一篇行程（"Day1 深圳湾公园→海上世界→蛇口老街…"），
截图或复制文案，打开路书，十几秒后拿到一组链接——点开就是地图 App 里排好途经点的路线。

**定位**：个人工具，自己和朋友用。不做账号、不做后端、不做行程管理——
行程的"家"在地图 App 里，路书只负责**把行程送进去**这一段，做完即退场。

**非目标**：不爬取小红书（只处理用户自己的截图/粘贴内容）；不自绘地图；不做社区分享。

---

## 2. 核心设计：两个 Key 配一次，之后每次都是「截图 → 出发 → 进导航」

产品只服务一个场景：**选截图，一键把全部目的地/途经点送进地图并开始导航**。
为此需要两个 Key（都是一次性配置，个人免费额度）：

| | 用途 | 为什么必须 |
|---|---|---|
| **① 识别 Key**（千问/豆包/Claude 任一） | 截图 → 地点列表 | 系统自带取字并非所有手机都有，识别必须走 AI |
| **② 地图 Key**（百度或高德） | 地点名 → 坐标 | 高德/百度的途经点参数把经纬度写死在 URI 里（一手核实），整程一条链接必须有坐标 |

**明确不做分段导航**：分段点击没有产品价值——用户自己在地图里手输即可。
因此出发的唯一目标是**整程一条链接**：

- 驾车且途经点 ≤3 → **百度 `navi` 排第一：带途经点直接进入导航态**（真·一键，SDK 逐字印证）
- 途经点 >3 或非驾车 → 高德 `route/plan` 全量携带（落规划页，App 里再点一次「开始导航」，如实标注）
- iOS → 恒追加 Apple 地图（途经点收纯地名，官方文档）
- 哪站定位失败 → **不降级**，标红那站引导改名/删除后重新出发（免 Key 的 OSM 定位仅作未填 Key 时的兜底，成功率低，如实提示）

粘贴文案保留为次选输入（有文字可复制时更快且免识别费），微信内只做「浏览器打开」引导。

## 3. 动线

单页三块，自上而下即使用顺序：

```
┌ 放行程 ──── 选截图（首选，AI 识别）｜ 粘贴文案（次选，粘贴即解析不设按钮）
├ 核路线 ──── 有序站点列表：改名 / 排序 / 删除 / 手动补；城市 + 出行方式两个小输入
└ 出发 ────── 常驻底栏一个按钮：静默定位全部站 → 一条整程链接（能直接进导航态的排最前）
              有站定位失败 → 标红引导修复，不生成残缺链接
```

设置（模型端点 / 地图 Key / 代理 / 高德途经点上限）全部收进折叠区——
默认路径一个配置都不需要碰。

**环境适配**在生成时决定，不让用户选：

- Android 浏览器 → scheme 全部包成 `intent://…#Intent;…;S.browser_fallback_url=…;end`
  （Chrome 25+ 禁止 `location.href` 直跳 scheme）
- iOS → 原生 scheme + Apple 地图链接
- 微信内 → 不做任何唤起尝试，直接显示「右上角 → 浏览器打开」引导
  （微信仅对合作方放行 scheme，实践中普遍失败，无参数可绕）
- 未装 App → 落到高德/百度网页版

## 4. 架构

五个纯逻辑层 + 一个 UI 层，全部 UMD、零依赖，node 与浏览器共用（逻辑层可单独单测）：

```
parse.js     文案 → 有序地点列表。纯本地。覆盖分天/序号/时间线/箭头串联/口语流水账，
             剥吹捧前缀与尾巴从句，低置信度标出来交给 UI
vision.js    截图 → 地点列表。协议双方言（openai 兼容 / anthropic），端点、模型、Key 全部 UI 可配
geocode.js   地点名 → GCJ-02 坐标。百度/高德可切，行程上下文就近消歧（离上一站近的候选优先）
links.js     站点 → 链接。按坐标有无、设备、途经点上限自动选通道、自动分段
net.js       统一出入口：图片压缩（长边 1280）、超时、可选代理转发、CORS 失败给出可诊断的错误
app.js + index.template.html + style.css     UI 与状态，localStorage 持久化
build.py     拼成单文件 index.html
proxy/worker.js   可选 Cloudflare Worker（域名白名单转发，只在撞 CORS 时需要）
```

**坐标系约定**：全链路只存 GCJ-02。生成百度链接时在 links.js 内部转 BD-09
（百度官方 SDK 即在客户端预转，`coord_type` 作用于途经点内部坐标一说无证据，不依赖）。
高德链接 `dev=0`。坐标顺序两家相反（高德经度在前、百度纬度在前、Apple 纬度在前），
全部封在 links.js 内，外部只见 `{name, lon, lat}`。

## 5. 关键决策及依据

**为什么是单文件静态 H5**
「多段路线」只能靠一条 URL 表达并唤起 App，天然是网页的能力；静态页零后端、
零维护、无备案义务，链接可以直接发给朋友。单文件只是打包形式——
一个 `index.html` 走到哪用到哪：本地打开、静态托管、传输助手发给朋友，全都成立。

**为什么百度是有 Key 档的首选**
它是三家里唯一"带途经点 + 直接进导航态"都满足的（`baidumap://map/navi` + `viaPoints`，
官方 Android SDK 反编译源码逐字印证），代价是官方上限 3 个途经点。
高德能带更多途经点但只能落到规划页——多点一次屏幕。两家链接都生成，现场挑。

**为什么 Apple 地图值得单列一档**
它是唯一途经点**不要坐标**的（官方原文 "address, coordinate, or a place name"），
也是全部结论中唯一读到官方文档原文的一条；且有 `start=N` 延迟自动开始导航。
iOS 18.4+ 可用，中国大陆数据源就是高德。这让"零 Key 一条链接走完全程"在 iOS 上成立。

**为什么识别层做成可配端点而不是绑定某家**
用户网络环境决定哪家模型可达（国内直连 / 代理 / 海外），这不该由工具替用户决定。
协议上收敛为两种方言（openai 兼容 / anthropic），预设四家但端点、模型名全部可改——
预设值中千问/豆包未能一手核对（官方文档域名在构建环境不可达），UI 里明示。

**为什么代理是可选件而不是标配**
默认动线里联网的只有免 Key 定位（Nominatim 自带 CORS 放行）；只有配了地图 Key 或模型 Key 直连国内服务端 API 时才可能撞 CORS。
撞了再部署 `proxy/worker.js`（十几行，域名白名单），不撞就永远不需要。

**为什么解析器宁可多召回**
删一条错误召回是一次点击，补一条漏掉的地点是一次输入 + 一次回忆。
所以噪声行整行丢弃的规则收紧、低置信度项保留并标色，由列表 UI 消化误差。

## 6. 部署与可移植

- **最简**：把 `index.html` 发到手机，浏览器打开。完。
- **给朋友用**：静态托管（Cloudflare Pages / Vercel / 任意对象存储）。
  注意 `*.pages.dev` / `*.vercel.app` 默认域名在国内受 DNS 污染，**必须绑自定义域名**；
  境外托管无备案义务（备案是合规问题，DNS 污染是网络问题，两者独立）。
- **可移植**：整个目录零外部依赖、不引用仓库内其他任何东西——
  想拆成独立仓库，`xhs2nav/` 整个拷走即是全部。

**Key 与隐私**：所有 Key 存在使用者自己浏览器的 localStorage，不经过任何第三方；
截图只发给用户自己配置的模型端点。要分享给别人用且不想暴露 Key，
把 Key 放进 Worker 代理的环境变量，页面侧留空。

## 7. 边界（据实）

- 微信内唤起地图 App：不可行，只做引导不做尝试。
- 高德"多途经点 + 一键进导航"：结构性做不到（`navi` 无途经点参数位），文案如实写"再点一次出发"。
- 途经点超上限（百度 >3、高德 >3~10）、iOS 端高德非空 via、Apple 地图国内中文地名质量：
  **未实测**，UI 与文档均已标注，不承诺。
- 识别质量以"可用"为目标而非"全对"——核路线这一步就是为此存在的。

## 8. 路线图

- **v1（现在）**：上述全部四档 + 三端适配，端到端测试齐（Android/iOS 双 UA，零 JS 错误）。
- **v2**：真机实测清单逐项定论（RESEARCH.md §四），按结果收紧/放开途经点上限与链接顺序；
  地点多候选确认 UI（当前自动就近选，错了只能改名重搜）。
- **v3**：iOS 快捷指令入口（截图 → 分享菜单 → 直接出结果）；
  Android PWA + Web Share Target；`start=N` 实测通过则 iOS 默认"自动出发"。
