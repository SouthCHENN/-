核路线

点名字可直接改，↑↓ 调顺序。绿圈 = 已拿到坐标。
点「出发」时工具自动用「② 地图 Key」给每一站定位，然后生成一条带全部途经点的链接—— 驾车且途经点 ≤3 时百度可直接进入导航态。哪站没定位到会标红，改个名再出发即可（不会退成分段点击）。

设置

① 识别 Key（截图识别用，必填一次）
千问和豆包的 endpoint 与模型名没能一手核对（构建环境访问不了 help.aliyun.com / volcengine.com）， 按公开检索填的默认值，以官方控制台为准，填错了在这里改即可。 豆包的 model 通常是控制台接入点 ID（ep- 开头）而不是模型名。
② 地图 Key（定位途经点用，必填一次）
百度：lbsyun.baidu.com 创建「服务端」应用并开通地点检索。高德：console.amap.com 创建「Web服务」Key。 没填时会退而求其次用免费的 OpenStreetMap 定位——能用但成功率和精度都更低，建议填。
代理（撞 CORS 时才需要）
浏览器直连大模型和地图的服务端 API 大概率被 CORS 拦。填了代理后，所有外部请求会转发过去。 仓库里的 proxy/worker.js 是一个可直接部署到 Cloudflare Workers 的最小实现。
高德途经点上限
3 个是两家都保证的安全值（百度官方明文上限，也是高德 App 里手动添加的上限）。 高德的 URI 解析层已确认无上限、无截断（客户端代码里是全量遍历数组）， 但下游路线规划页是否二次截断到 UI 上限，只能真机实测。

这个工具能做到什么

已核实（官方文档原文）：Apple 地图 maps.apple.com/directions 的 waypoint 参数「接受地址、坐标或地名」，且「重复该参数即可指定多个途经点」。 这是三家里唯一途经点不要坐标的，也是唯一读到官方文档原文的一条。配 start=N 可延迟 N 秒自动开始导航。需 iOS 18.4+，国内用的是高德数据。

已核实：百度 baidumap://map/navi 带 viaPoints 可以带途经点直接进导航态（官方 Android SDK 反编译源码 + iOS 头文件 + 官方 Flutter 插件三链印证），官方上限 3 个途经点。

已核实：高德带途经点只能落到路线规划页，需要再点一次「开始导航」—— 能一键直达导航的 androidamap://navi 结构上没有途经点参数位。

已核实：高德的 vialons/vialats/vianames 由高德 App 自身的解析代码 逐字读取并按 | 切分。注意 vian 的值被读取后即丢弃， 真正的硬约束是 vialons 与 vialats 长度必须相等，否则整组途经点被静默丢弃。

待你实测：iOS 端对非空 via 的处理无代码可查；高德 t 参数的枚举无证据； 百度 direction 上的 viaPoints 官方 SDK 没拼；两家传 3 个以上途经点的行为。
